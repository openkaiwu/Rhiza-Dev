## 1. 当前可体验的产品闭环

Rhiza 是单机 Web Early Preview。它把长期讨论组织为 Workspace、Discussion Node、Semantic Edge、Context 与可解释的模型执行记录。

当前用户可以：

1. 创建、切换、重命名、归档和恢复多个 Workspace；本地 actor 与 membership 约束 Workspace 间读写。
2. 在 Node 内进行流式对话、停止、重试、重新生成、编辑重发，并使用 Markdown、代码、公式、Mermaid、Reasoning、Tool Call 与 Token Usage 展示。
3. 从消息或划线文本发起临时/正式支线，保留后生成正式 Node 与 `derived-from` Relation，并将结论合并回主线。
4. 在 Conversation Graph 中搜索、缩放、平移、拖拽、创建 Relation、归档/恢复 Node，并持久化布局坐标。
5. 管理 Active / Recommended / Excluded Context，使用 Auto / Assisted / Strict 模式，并查看每次正式 Chat 的不可变 Context Manifest。
6. 添加附件；附件以 Resource/ResourceVersion 表达逻辑与版本身份，Blob 按 SHA-256 校验并 content-addressed 存储。
7. 查看低频业务活动时间线，以及每次模型调用的执行历史、模型/endpoint 身份、输入 hash、错误、取消与 Retry/Regenerate 谱系。
8. 配置多个 OpenAI-compatible Provider 与模型；API Key 只以本机 AES-256-GCM 密钥加密保存，浏览器不读取明文。

默认生产持久化后端是 embedded PGlite；配置 `DATABASE_URL` 后使用同一 relational Repository 与 migration 的外部 PostgreSQL。JSON WorkspaceStore 只保留作 characterization fixture 和显式 `workspace:import-json` 输入，不是生产默认写路径。

## 2. 当前实现架构

| 层 | 已落地职责 | 主要位置 |
| --- | --- | --- |
| Web | Workspace 选择、Chat/Graph/Context/RunHistory 表现与局部交互状态 | `src/App.tsx`、`src/components/`、`src/api.ts` |
| HTTP 与 Scope | legacy default 路径兼容、`/api/v1/workspaces/:workspaceId` scope、local actor 注入与输入边界 | `server/http/app.ts`、`server/identity/` |
| Application | Command/Query envelope、membership/scope 检查、Chat 编排、生命周期与错误归一 | `server/application/`、`server/contracts/application.ts` |
| 事务与状态 | State、Journal、Receipt、Run mutation 的单一事务 seam | `WorkspaceUnitOfWork`、`server/postgres-store.ts`、`server/embedded-store.ts` |
| 资源与 Host | ResourceVersion、digest、Blob promote、backfill、当前 Node/headless capability | `server/infrastructure/`、`server/application/ports/host-runtime.ts` |
| Runtime | Provider Catalog/Model Spec 冻结、OpenAI-compatible 调用与 Runtime Event 归一 | `server/provider-*.ts`、`server/ai-runtime.ts` |

普通和临时 Chat 都先创建 durable `ExecutionRun`，再进行外部模型调用。成功 Run 与正式消息、Manifest、Journal 和 Receipt 由 guarded completion 原子提交；失败、取消和中断保留终态，晚到结果不能覆盖。临时 Chat 不创建正式消息/Node，但不会绕过执行审计。Runtime trace 与短暂 SSE 状态不进入 Domain Journal。

`workspace_events` 只记录低频已提交语义事实，按 Workspace sequence 严格排序；`command_receipts` 支持同一 command id 的稳定重放。Resource/ResourceVersion、Manifest 与 Run 输入均按相应约束保护不可变历史。具有 Run 输入或历史引用的 Node 不可物理 Purge，必须继续 Archive。

## 3. 已接受的 V4.2 基础能力

### M03：Workspace 与最小 Identity

已实现 Workspace directory、membership、ActorRef/ScopeRef、scoped 路径与前端 stale-response guard。它是本地单用户的确定性 identity seam，不是账号系统、会话或通用 RBAC。

### M04：Resource、Blob 与最小 Host Runtime Port

ResourceVersion 使用稳定逻辑 ref 与 SHA-256 内容 identity。Blob 提交顺序为 temp write → digest verify → atomic promote → relational commit；数据库失败最多留下可由 grace-period GC 回收的 orphan blob，不产生 committed dangling reference。M04 只覆盖当前 Chat 需要的 file/path/blob/credential seam；spawn、PTY、Desktop 与真实跨平台 host matrix 仍后移。

### M05：Domain Journal 与事务事实层

生产 relational adapter 通过 `WorkspaceUnitOfWork` 在同一事务完成 command lock、receipt lookup、scope/revision guard、Current State mutation、sequence reservation、Journal append、semantic checksum 与 Receipt commit。历史 Workspace 通过 `workspace.baseline.backfilled` 建立 sequence-1 起点；已有业务 tail 而缺失 baseline 时以 `JOURNAL_BASELINE_ORDER_CONFLICT` 失败，绝不重写 sequence。

### M06：Chat ExecutionRun

每次普通或临时模型调用都有 immutable input、ContextEnvelope hash、Model/ProviderEndpoint snapshot、terminal status 与可选 parentRunRef。取消先持久化终态再 abort Provider；Retry/Regenerate 创建新 Run，而不是覆盖旧 Run。启动恢复在服务接受请求前执行；PostgreSQL 使用单 runtime advisory lock。`RunHistory` 展示状态、错误、telemetry、hash 与重试入口。

## 4. 尚未交付的边界

- **M09–M11**：Replay/Provenance/Portable Bundle、legacy 写路径关闭与 Chat-era architecture convergence。
- **M12–M17**：日常 Chat 产品化、Workspace/Graph/Context 产品体验、多模型协作、导入导出/备份恢复以及真实长期使用验收。
- **M18–M24**：信息架构升级、Project State/Artifact/Knowledge/Decision、Task/Workstream、Search、Context Intelligence、External Executor。
- **M25–M27**：Workflow、Multi-Agent、Full Auto；当前没有 Workflow event catalog、调度器、Assignment/RunGroup 或 Agent Harness。
- **M28–M32**：Adaptive Routing、Desktop/跨平台、Memory、Plugin 与 Control Plane。

当前 Preview 也仍有产品级限制：没有账号、登录、协作角色、跨设备同步或开放公网的权限模型；Context 的 Assisted/Recommended 语义、Project State、完整 replay、导入导出和大图性能均未完成。活动时间线与执行历史分别解释业务事实和单次模型调用，二者都不等于完整可回放工作流。
