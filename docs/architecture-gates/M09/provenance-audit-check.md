# Provenance coverage audit — partial M09 evidence

`m09:provenance:audit` requires exclusive Chat runtime ownership. Its SQL count query takes one PostgreSQL snapshot across every Workspace: it counts live Assistant outputs without a stored ProvenanceLink, links explicitly marked broken, and malformed or dangling recorded links. It checks every non-purged input reference resolves within the same Workspace, revision/branch source identities match the stored Message/Node, and recorded links match the direct reply input, Manifest, Run, model, endpoint and runtime snapshot. A second single-snapshot query selects recorded links and their Runs, decrypts sealed Run inputs, checks the input hash and compares the complete ordered `inputRefs` set with frozen history plus the direct reply. No message or Run body is logged; any mismatch or unavailable key fails the Gate. Embedded and PostgreSQL E2E fixtures verify missing, backfilled, broken and individually corrupted recorded fields, including extra dangling and extra valid input references; an encrypted Run fixture verifies deep decoding.

The two queries are not one transaction, so run this audit with the staging service stopped and no direct database writers; runtime ownership enforces the Rhiza side of that boundary. It does not prove every Replay policy, source Blob integrity, historical exported Bundle, or user-managed staging data; `provenance_replay` remains pending until those checks and the real staging audit pass.
