# M09 import recovery and clean-store round trip · 2026-09-28

`e2e/m09-import-sigkill.e2e.test.ts` starts a separate importer process, waits for a checkpoint, sends `SIGKILL`, reopens the destination, and resumes from the independently encrypted retained ZIP. Each of `validated`, `blobs-ready`, and an uncommitted `activating` transaction runs against both embedded PGlite and an isolated real PostgreSQL schema. All six cases pass with `DATABASE_URL` configured. Before recovery the checkpoint is durable but the target Workspace is absent; after recovery the checkpoint is activated, portable facts and graph-projection checksums match the source, the live ResourceVersion and frozen Run attachment point to the same target-scoped `sealed-v1` Blob with matching bytes, and a purged ResourceVersion remains a content-free tombstone. The PostgreSQL activation kill occurs after its project-row INSERT but before COMMIT, exercising server-side rollback.

Related regression coverage: `server/infrastructure/import-archive-retention.test.ts` kills an upload process and verifies the startup reclamation routine removes its transient plaintext, then kills reclamation between key destruction and descriptor removal and verifies idempotent cleanup. `server/infrastructure/node-host-runtime.test.ts` rejects corrupt or mismatched existing Blobs rather than replacing them. `e2e/m06-runs.e2e.test.ts` rejects missing Blob content and mismatched runtime/descriptor digests; its reopened-database import test rolls back a Journal write, resumes from the retained archive, verifies portable facts, graph checksum and resolved historical Context, then continues Chat and executes explicit Partial Replay. `e2e/m09-default-bundle.e2e.test.ts` exports an encrypted ResourceVersion from one clean production store and imports it through HTTP into another; logical facts and state checksum match while the destination gets a different scoped ciphertext reference.

The HTTP import test injects archive-retention failure and checks that a validated identity-bound checkpoint already exists while the target Workspace remains absent. A conflicting import is rejected before archive retention or checkpoint creation. Without a configured archive store, Purge still rejects every import checkpoint phase. With that store, Purge records the archive digest transactionally, resumes an interrupted key revocation, rejects a late import retry, and excludes the revoked archive from recovery pins. Real PostgreSQL concurrency coverage holds retention across a Workspace lock while Purge waits; legacy plaintext archives fail before the Purge transaction commits. A SIGKILL before descriptor publication leaves an orphan key that startup reclaim revokes. These checks do not close Run/resource/backup replica erasure.
