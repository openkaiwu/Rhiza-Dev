# M16 security tooling and reproduction

The five historical detections have been privately reviewed: three are public tokenizer version literals; two README/archive matches cross an empty API Key assignment and capture the following public boolean configuration assignment. Actual captured values and source Git blobs were checked without publishing detector snippets. Five explicit decisions in `tools/security-history-reviews.json` bind the pinned tool version, rule/file hashes, immutable commit and exact start/end lines, with source Blob digests as evidence. They apply only to Git history. The five raw findings remain in reports, alongside reviewed/unreviewed counts; no filename/rule wildcard or detector-rule change is used. Formal security/export Gate acceptance remains open.

## Pinned installation

Use `pnpm run security:install`, requiring curl and tar on Darwin/Linux arm64/x64. Installation is local under ignored `.rhiza/tools/gitleaks/8.30.1/`. `tools/gitleaks.lock.json` pins the [official release](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1), checksum manifest and archive SHA256. Verify both before extracting named members to memory; scans recheck the executable against that archive and verify version. Keep the [MIT notice](https://github.com/gitleaks/gitleaks/blob/v8.30.1/LICENSE), copied to `licenses/upstream/Gitleaks-MIT.txt` and alongside the installed executable. Host curl resolved the observed native-fetch release redirect timeout.

## Checks

- `pnpm run security:fixtures`: temporary inert GitHub/AWS/generic key and ZIP fixtures; expected 4/4 detections, 100%, sanitized=true and clean negative=true. Final reproduction achieved these values; fixtures are removed afterward.
- `pnpm run security:scan`: full Git history, including archives to depth 1 and decoding to depth 2; nonzero for any unreviewed finding. Current historical findings remain visible in `security.json`; reviewed findings produce `REVIEWED_HISTORY_FINDINGS`, rather than pretending the detector found nothing. New commits or changed rule/location/line ranges cannot reuse a decision.
- `pnpm run security:export .rhiza/exports/workspace.rhiza`: validates the actual Bundle, including descriptor/reference/history checks, then scans the expanded private directory and removes it on success or failure. The original artifact is unchanged. Passing a `.rhiza` path directly to generic Gitleaks misses its compressed content because the extension is not recognized; do not use the generic `dir` command as export evidence. Detector patterns remain bounded and do not claim exhaustive DLP.
- `pnpm run security:export:fixtures`: actual exports through `NodePortableBundle`; the sanitized negative control produced zero findings, and a synthetic credential present only in an attachment Blob produced one finding. Both reports were sanitized. Token/path/location operational extensions were omitted while user-authored strings remained intact. Fixtures are private and removed afterward.
- `pnpm run security:checks`: sanitizer/checksum/review-binding regressions, positive fixtures, actual Bundle export fixtures and full-history scan. All component checks passed locally after explicit review; the aggregate command and remote CI job remain to be run in final delivery verification. The CI job stays blocking for any unreviewed finding or invalid/stale review configuration.

Reports contain counts, lines, hashed rule/location/commit references, reviewed classification, source Blob digests and bounds. They contain no detector match, Secret, snippet, filename, absolute path, caller parameter, key or endpoint credential. Filenames are hashed because they can contain credentials. Raw child stdout/stderr is never forwarded. Private temporary reports are removed after success or failure. Explicit default rules, empty ignore files and ignored inline allow comments prevent caller configuration from suppressing checks. Directory/export scans never apply historical review decisions. Review configuration rejects wildcards, duplicate identities, malformed fields and tool-version drift before scanning.

Failure codes: `SECRET_FINDINGS`, `TOOL_DOWNLOAD_FAILED`, `TOOL_CHECKSUM_MISMATCH`, `TOOL_CHECKSUM_MANIFEST_MISMATCH`, `GITLEAKS_NOT_INSTALLED`, `UNSUPPORTED_PINNED_TOOL_PLATFORM`, `TOOL_VERSION_MISMATCH`, `INVALID_SCAN_REPORT`, `INVALID_HISTORY_REVIEW`, `SCAN_EXECUTION_FAILED`. Unexpected failures become `SECURITY_CHECK_FAILED`, with exit 1. A missing tool is never skipped; no system executable fallback is used.

## Remaining acceptance

The historical candidate review is complete and bounded to the five original detections. Any new review requires private source/captured-value evidence and an explicit immutable identity; it must not become a filename/value/regex allowlist. Synthetic real-export safety checks pass; an explicit deployment artifact scan, remote CI and production UI integration remain pending. Existing Bundle descriptor/portable DTO location stripping and hostile-archive checks remain intact. This unit does not change Bundle format, stored bodies or keys.

Newer metadata exclusions may remove keys bound by an older portable Journal checksum. Re-export verifies the original state checksum before recomputing the sanitized checksum; corrupted business history still fails. This compatibility rule does not bypass import validation or rewrite arbitrary business strings.
